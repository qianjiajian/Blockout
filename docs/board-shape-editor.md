# 棋盘造型编辑器

这是给关卡设计使用的本地工具。它把每关的逻辑区域拆成可点击的小格：`#` 是棋盘，`.` 是虚空。编辑结果直接驱动正式碰撞、连续 ImageGen 托盘外沿、内部网格和求解器，不是只改变外观的遮罩。

## 启动

在项目根目录运行：

```powershell
pnpm board:editor
```

浏览器会打开 `http://127.0.0.1:5173/board-editor.html`。必须使用这一命令启动，页面上的“验证并保存到项目”才会启用；静态构建中的编辑器仍可编辑和导出 JSON，但不能改写项目文件。

## 基本操作

1. 在“选择关卡”中选择第 1–100 关。
2. 选择“铺地”或“挖空”，在小格上按住并拖动。鼠标右键拖动始终是挖空；快捷键 `B`/`E` 可切换工具。
3. 黄色框是出口、初始方块或卷帘占用的必需格，不能挖空；正式 100 关不使用棋盘内部固定障碍。
4. “铺满”会填充全部非障碍格；“仅保留必需格”可作为从零塑形的起点；“恢复项目版”会回到当前项目数据。
5. 点击“验证可解性”运行与正式 100 关测试相同的 A* 求解器。工具会检查真实可解性、轮廓重复、内部封闭死格、困难/超难关必要腾挪和章末节奏；内部死格必须铺平或连通到外沿后才能保存。
6. 点击“验证并保存到项目”。只有验证通过才会写入 `src/core/boardShapes.ts`，同时自动更新该关最少拖动数。

一次连续拖动只占一个撤销步骤。未保存内容会按关卡保存在浏览器本地草稿中，切关或刷新不会丢失。

## 安全与备份

- 写入接口只监听本机回环访问，只允许修改第 1–100 关的轮廓数组和最少拖动覆盖值，不接收任意文件路径。
- 每次真正写入前，原始 `boardShapes.ts` 会备份到 `tools/board-editor-backups/`。该目录不进入版本控制。
- 关卡尺寸不能通过此编辑器修改；如需同时改变宽高、方块、出口、障碍或机关，应修改关卡源数据并重新执行完整验证。
- 保存一关后建议运行 `pnpm verify`，确认 100 关、真实 Pointer 回放、Web 和微信构建没有回退。

## JSON 交换

“复制 JSON”和“下载 JSON”可把当前轮廓交给其他人或留档；“导入 JSON”和“应用下方文本”只写入当前浏览器草稿，不会绕过验证直接修改项目。格式为：

```json
{
  "format": "block-out-board-shape/v1",
  "levelId": 15,
  "width": 7,
  "height": 8,
  "rows": [".####..", "#######"]
}
```

实际 `rows` 必须完整包含当前关卡的所有行，每一行宽度必须一致。
