## 承继v1.31：新机制解锁首关及随后几个简单关采用少量色块、大量该新机制

## 承继v1.30：同类机制实例数量按关卡难度设计，不默认只有一个

用户明确：“为什么都是新机制的数量都是一个，可以根据难度多放几个”。本版把按难度使用多个同类实例列为后续设计要求；不是新增运行机制，也不把用户的许可解读为所有关卡强制加机关。v1.17已经允许主机制多个实例，v1.21允许多种已解锁机制组合；本版纠正设计时默认只选单个实例的保守做法。旧32份冻结正文、manifest条目和既有证据保留，runtime不变。

1. 区分机制种类、同类实例数量和每个实例的计数/库存。例如两台生成器是两个实例，每台出几件是各自库存；两片卷帘与一片卷帘计数提高不是同一种改动。设计与评审卡分别列出，不能只增加单个机关数字来冒充已经落实多个机关。
2. 在已授权的关卡设计/重做中，根据难度、棋盘空间和核心决策主动选择同类实例数量，不默认固定为一个。“突出一个主机制”不限制同类实例，也不撤销多机制共同构成核心的许可；首次引入关号及所有机制兼容规则保持。
3. 以下为实施方向，不声称用户批准了新的固定数量门槛：简单教学/巩固以清楚表现因果和低信息负担为主，可以少量；普通关可安排多个同类机关产生可读的先后与让位；困难/超难可由多实例形成通路、工作位、解锁或补货顺序的相互制约。教学关没有硬性“至多一个”，困难关也不机械规定“至少两个”；不设一律1/2/3/4的配额，不要求机关数随关号或难度严格递增，不要求之后每关都出现最新机制。

## 4. 结算与一致性

1. 每次整块或剥层只计一次清除：开始离场按原时点使冰门/可见冰块/卷帘减数，登记一次全体翻门事件并在对应动画结束时实际切换；不因露内芯或完成回调再扣一次其他计数。钥匙只按本体移除结算。headless无动画模式即时完成该翻门事件。
2. 先按本次事件前可见性扣冰，再揭卷帘/电梯；新露冰不追扣。炸弹解除最后限制当帧不追扣以前时间，未选中也会计时。
3. 投放/揭层确定性串行，完整足迹无碰撞，必须终止。自动投放的已发生事件、拖动取消与撤销保持一致，不丢块、不复制，不回拨墙钟。
4. 电梯不只检查原成员ID是否消失；任意外来块压区也要等待。隐藏批次整体释放，不产生跨层同时占格。
5. 结束、失败、暂停后不得继续投放、重复清除/翻转或计数穿零；仍有效的末次离场及暂停后恢复按第0.1节处理，失效回调不补发。快照、克隆、撤销及独立回放的冰/门/队列/炸弹、冻结剩余与待完成事件状态一致；旧回调不得越过恢复后的事件有效性检查。
6. 视觉动画不独立扣数或改open；GUI有效离场完成回调提交模型翻门事件，视觉表现同一模型结果。旧运行兼容路径保留但不作为新数据机制；本次21–200显式使用runtimeProfile v1.4（`revised-2026-09-23-v1.4`），承继v1.13动画时序并实现时间冻结；不能只换标签而未实现对应行为。
