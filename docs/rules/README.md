## 三种信息严格分开

| 文件 | 用途 | 修改要求 |
|---|---|---|
| 锁定规则正文及manifest中已有版本条目 | 规则、验收要求、已知待确认边界 | 不原地改写；用户确认变更后新增版本 |
| `WORKSTATE.md` | 当前执行进度、验证证据、阻塞、下一步 | 随真实工作更新，不能改写规则 |
| 项目根目录 `AGENTS.md` | 指导新任务和恢复任务先读取上述文件 | 保持指针准确，不复制出第二份独立规则 |

采用项目 `AGENTS.md` 是依据 OpenAI Docs 的项目指令加载方式：Codex在任务开始前读取适用的项目指令。上下文恢复后的重新读取步骤也写入入口，而不是声称聊天记忆永不丢失。[官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

## 每次开始或恢复

1. 阅读manifest、完整规则正文和WORKSTATE。
2. 在项目根目录执行 `node tools/verify-rules-lock.mjs`，确认锁定内容未改变。
3. 核对当前工作区和测试，再从WORKSTATE的下一步继续。
4. 规则与实现不一致时在授权范围内修实现；21–30流程按v1.20自主整批设计与正式接入，不再索取相同确认；改图权限/分档按v1.19，高级机制/组合按v1.21，难度合理性按v1.18分别评审。新布局保持实际原棋盘结构，不把旧来源配额当新验收条件。账户体力按v1.16，时间冻结按v1.14，M05承继v1.13事件合同。历史任务与新授权范围分别记录，未知来源不冒充已核实，新原创规格必须写全并验证，不能改冻结文档来让测试通过。

规则校验采用 UTF-8 文本，去除开头BOM，并将CRLF/CR统一为LF后做SHA-256。除这些跨平台编码差异外，文字、空格、标点、末尾换行变化都会被检出。工具只读，不提供“自动更新hash”或“接受当前变化”选项。

此锁防止意外漂移，不是文件系统只读权限或防篡改签名；有权限同时改正文与manifest的人仍可改文件，必须通过版本记录和代码评审遵守流程。当前文件已落盘，不代表已提交Git、远端备份或发布到手机。

## 修改规则的唯一正常流程

1. 取得用户明确的新规则指令；“继续”“修复BUG”“求解太慢”不构成放宽规则的授权。
2. 新建版本文档，例如 `docs/mechanism-rules-v1.1.0.md`，列清相对前版的改动、依据及待确认项；不能覆盖v1.0.0。
3. 为新正文计算校验值，在manifest追加版本条目；用户确认后切换 `activeVersion`，更新AGENTS指针。
4. 棋盘机制有行为变化时使用新的runtimeProfile，避免同一profile对应两套棋盘玩法；v1.16为外围体力业务迁移，v1.17为设计组织原则，v1.18/v1.19为设计评审/协作范围及验收，均不改棋盘机制或关卡profile，按新版本完整正文单独记录。
5. 对受影响实现、候选、回放和下界证书重新验收；旧证据不能无条件复用。
6. 更新WORKSTATE，并运行规则校验及校验工具自测。
