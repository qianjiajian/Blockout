# Block Out! 冰冻翻转门解冻时序与冰层显示 v1.90.0

- Rule ID: blockout-rules-v1.90.0
- Runtime profile: revised-2026-09-27-v1.5
- Frozen on: 2026-09-27
- 完整承继 v1.89.0；本版仅覆盖冰冻翻转门参与翻转的时机，并修复冰层透明度为0的显示错误。

## 用户明确指令

用户要求“被冰冻的翻转门，不触发翻转门逻辑，接触冰冻后开始执行翻转门逻辑，然后修复透明度0的BUG，并把这条规则记住”。其中“接触冰冻”按解除冰冻理解，随后用户明确选择：“本次只解冻，下一次消除或剥壳后开始翻转”。

## 生效行为

1. 翻转门 frozen > 0 时保持既有 open 状态，不参与本体清除、成功剥壳或火箭清除导致的翻转，也不累计待补发翻转次数。冰冻期间仍禁止色块通过，计数按既有规则递减。
2. 冰冻计数从1减到0的本次事件只解冻，不翻转；保留该门原开关状态。之后下一次成功本体清除或剥壳才参与翻转。火箭仍属于一次清除；脉冲仅按既有数量解除冻结，不自行产生翻转事件。
3. 每次成功清除或剥壳，在该次冰冻计数减少之前确定未冻结门的ID集合。延迟到离场/剥壳动画完成时，仅切换这批门；不能用回调时的冻结状态重新选择，不能让冻结期间的旧事件在解冻后补翻。
4. 继续承继v1.13的动画完成时点：GUI在对应离场/剥壳动画完成后才改变实际open及播放翻转；headless无动画立即完成。多个事件独立且恰好完成一次，撤销/重开/失败的失效回调不得补触发；暂停/后台沿用既有冻结动画规则，不新增全局输入锁。
5. 冻结翻转门统一使用不透明冰层（静态overlayAlpha=1），不能因底层open/closed或actionable/latent状态把冰层设为0。正式素材和备用绘制均须显示；闭合门板不能覆盖冰层。解冻后移除冰层，按实际开关状态绘制正常翻转门及方向提示，数字继续表示剩余冰冻计数。
