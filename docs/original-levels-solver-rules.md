# 原创关卡 101–120：求解器可执行规则

本规则文件是 `blockout-original-levels-101-120.json` 的机器可执行解释。JSON 中没有定义逐块金币、全局出口队列、数字边栏绑定目标、冰冻层数等字段，因此求解器只采用下述明确且可复算的缺省值；不会从难度标签或 D 值反推玩法。

已停用机制：钥匙方块、钥匙与锁、双向箭头方块。关卡配置、补全器和求解器均会拒绝这些机制；出口上的方向提示只表示出口朝向，不会限制色块的拖拽轴向。

## 一、基础棋盘与移动

1. `board` 固定为 6 行 × 8 列。
2. `.` 是可移动空格；`_` 是棋盘轮廓外或独立面板间隔；大写字母是色块单元。
3. 同一字母的所有正交相连单元组成一个刚性色块。色块不可旋转、镜像、拆分，也不能越过 `_`。
4. 一次基础步是把一个色块整体平移一格，上下左右四方向之一；目标单元必须全部是可玩格且未被其他色块占用。这等价于色块与相邻空位交换。
5. 搜索器可把同一色块连续若干个基础步合并为一个宏动作，但最少步数仍按逐格平移累计。
6. 色块任一单元接触同色出口所在的边界格即触发消除；不要求松手。色块初始已经接触可用出口时，向出口拉出计 1 步。
7. `_` 上的出口属于配置错误，因为该出口没有相邻棋盘格。

## 二、出口、颜色顺序和胜利

1. `exits` 中每项定义一个同时存在的出口；出口只接受 `board_legend` 指定的同色色块。
2. 当前 JSON 没有 `exit_sequence` 字段，因此不添加全局颜色队列。每次消除均重新检查颜色、数字、冰冻和图案前置条件；不允许在前置条件未满足时绕过到下一出口。钥匙锁机制已删除，不参与任何判定。
3. 若将来需要固定红→蓝→黄之类的全局顺序，必须在关卡中显式增加 `exit_sequence`，否则求解器不会猜测。
4. 所有色块移出、所有终局数字条件满足后，关卡完成。完成时一次性获得 `target_coins`；由于配置没有逐块金币字段，金币不参与路径选择。

## 三、数字机制

### 数字方块

- `number_elements` 的 `block` 指定数字所属色块。
- 数值表示该色块消除前，其他已消除色块累计覆盖的棋盘单元数门槛。
- 例如数值 7 表示累计清除至少 7 个单元后，该数字块才可从出口消除。
- 数字块在门槛未满足时仍可移动，只是不能消除。

### 数字边栏、侧边计数装置

- 每消除一个色块，按该色块单元数增加全局清除进度。
- 计数装置的剩余值为 `max(0, value - cleared_cells)`。
- 若装置的 `position` 与某出口的边和序号完全相同，补全配置会写入 `role="exit_count_gate"`、`gates_exit_id` 和出口侧的 `counter_gate_id`；数字归零前该出口关闭，不采用“最近出口”推测绑定，也不显示钥匙或挂锁。
- 没有与出口精确重合的装置是终局计数目标：全部色块清除后的累计单元数必须达到该值。

### 形状计数装置

- `mechanism_config.形状计数装置` 按数组顺序与同类型数字元素配对。
- `L形`、`长条`等名称按色块初始形状分类；只有匹配形状的已清除单元才计入对应计数。
- 与出口位置重合时锁出口，否则作为终局目标。

## 四、状态型机制

### 冰冻效果

- `mechanism_config.冰冻效果` 中的色块初始冻结 1 层，冻结时不可移动。
- 每当任意非该色块成功消除，冻结层数减 1；降到 0 后立即可移动。

### 嵌套方块

- `inner_block` 初始不可移动、不可消除，但仍占据自己的棋盘单元。
- `outer_block` 消除后，内层块激活。
- 配置没有重叠坐标，因此不把内层块瞬移到外层位置。

### 图案方块

- 配置中列出的图案块必须在同色普通块已经消除后才能消除。
- 若初始不存在同色普通块，则至少先消除任意一个非图案块。
- 图案块在此前仍可移动。

## 五、棋盘拓扑和形状机制

### 异形方块

- 字符图给出的多格轮廓是唯一有效形状，整体刚性平移，不旋转、不拆分。
- `mechanism_config` 中的形状文字只用于核验引用的字母存在。

### 阶梯形通道

- `_` 裁出的逐行收缩轮廓就是阶梯边界；任何单元不得越界。
- 描述性文字不会额外生成隐藏墙。

### 分离式双面板

- 全 `_` 分隔行或列把可玩区域分为独立连通分量；色块不能直接跨越。
- 只能在本面板边界的同色出口消除；配置文字中的转移不会凭空传送色块。

### 中部通道

- 配置列出的通道格必须在字符图中是可玩格。
- 通道本身不改变平移方向；通行能力由色块形状、空位和刚性碰撞自然决定。

### 纵向通道

- 色块锚点位于配置通道格时，只允许纵向平移；离开通道后恢复四方向平移。

### T形通道

- `stem` 与 `bar` 描述的可玩区域构成 T 形连接；色块只能在交汇格由竖向转横向或由横向转竖向。
- 实际可玩边界仍以字符图为准。

### 环形通道

- 配置给出的内核矩形不可被色块锚点穿越；色块只能沿内核外围可玩格绕行。
- “非闭合回转道”允许从字符图现有缺口进入或退出；求解器不生成配置中未标出的传送或单向运动。

## 六、限时与耗时估算

1. 搜索先求逻辑最少基础步数，再根据求解路径估算操作耗时。
2. 估算式：`0.55 × 基础步 + 0.75 × 消除次数 + 0.30 × 转向次数 + 0.25 × 触发机关次数 + 2.0` 秒。
3. 倒计时从第一次动作开始；估算耗时大于 `time_limit_sec` 时标为“逻辑可解但超时”，不标为限时可解。
4. `expected_clear_time_s` 只用于结果偏差比较，不参与搜索和规则判定。

## 七、搜索与结论等级

1. 使用 A*；每个宏动作内部用 BFS 求同一色块在其他色块不动时的最短逐格路径。
2. 启发式为所有剩余色块忽略其他色块时到同色出口的最短距离之和，不超过真实剩余步数。
3. 搜索完整耗尽且无解时输出“不可解”；静态配置错误直接输出“配置错误”。
4. 达到状态上限仍未完成时输出“未判定”，不会把资源上限误报成不可解。
5. 卡死报告优先给出：无有效同色出口、出口位于 `_`、所有可移动块被占位封死、数字/冰冻/嵌套前置条件循环锁死。
