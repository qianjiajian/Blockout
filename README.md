## 本地运行

```powershell
pnpm install
pnpm art:optimize
pnpm dev
```

浏览器打开 `http://127.0.0.1:5173/`。测试与构建：

```powershell
pnpm test
pnpm docs:levels
pnpm docs:economy
pnpm levels:freeze:verify
pnpm verify:system-only
pnpm build
pnpm release:verify
pnpm wechat:verify
```

`levels:freeze:verify` 是纯系统迭代的可选关卡锁。只有在获准的关卡修改已完成、全季 Pointer 与文档门禁均确认通过后，才可显式运行 `pnpm levels:freeze:capture -- --confirm --label=<快照名>` 重建基线；每次捕获还会在 `playtest-results/level-freeze-baselines` 留下不可覆盖的同名归档。普通构建与 `pnpm verify` 不会自行改写该快照。

首次运行浏览器回归前安装 Chromium，然后可一键执行完整验收：

```powershell
pnpm exec playwright install chromium
pnpm verify
```

原创关卡生产链可通过 `pnpm levels:original:pipeline` 重新导出：它会按 Block Out 专用的“缓冲紧张度 / 隐藏信息 / 机制多样性 / 出口竞争”公式评分，拟合新版竞品 Lv1–100 曲线，合并正式求解证据，并执行旋转、镜像和换色均无法绕过的原创性门禁。流程与生成模板分别见 [原创关卡生产流程](docs/blockout-original-level-pipeline.md)和 [原创关卡 Prompt 模板](docs/blockout-original-level-prompt-template.md)。

`pnpm verify` 会先检查运行素材的路径、尺寸、Alpha、图集格数、顺序、清单覆盖与发布显示密度，再依次运行 TypeScript、关卡设计与经济报告漂移检查、规则/关卡/机制事件/道具/微信触摸/自适应热区测试及完整真实指针浏览器回归（含五档难度现场复算与代表截图、收藏一次性发现提示、首次隐藏启动、24/82 张常驻美术首屏分层加载、18 张正式页面美术互斥按需加载、6 路并发上限、慢资源/资源失败恢复、完整停靠位 A* 现场求解、完整混合拖拽、排行榜、五页导航、三态事务存档、低端性能与内存生命周期）。全季回归后会用刚生成的 Pointer 证据刷新并二次校验关卡设计与经济报告，再完成 Web 与微信构建，因此命令结束后不会留下“测试已更新、文档仍旧”的漂移状态。需要在纯系统迭代中禁止任何关卡与难度语义变化时，改用 `pnpm verify:system-only`；普通 `verify` 与构建允许已授权的关卡设计对话更新关卡。工作区已在 `pnpm-workspace.yaml` 中仅允许 esbuild 的必要安装脚本。
