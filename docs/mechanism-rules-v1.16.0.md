用户明确要求：“把体力规则改成和他们一模一样”。本轮按已核实的普通体力行为落地；BP与广告因当前没有资格/奖励接口尚未接入，边界在下文明确，不声称全部商业系统已一致。关卡设计及计时开钟不因体力迁移改变。本版依据Block Out Puzzle 1.0.183原生链核验，证据为`deliverables/competitor-lives-2026-09-23/audit.md`；先记录变更依据、明确规则和实现约定，再冻结完整正文。旧18份冻结正文及manifest条目保持。

### A. 普通体力及扣返规则

1. 新存档初始5点，普通自然恢复上限5点；上限是恢复及补满目标，不是奖励余额硬上限。已有存档继续保留合法余额、恢复进度及无限体力截止，不清档、不重置为5、不追溯扣除历史局的体力。
2. 少于5点时每1800秒恢复1点，达到5点停止恢复并清除恢复锚点。首次从已满降至缺心时启动30分钟恢复；已经缺心时再次扣心不重置恢复进度。按真实时间补算离线、后台及暂停期间经过的完整周期，未满时保留不足一个周期的余数；满心期间不储存额外恢复额度。这里是账户体力的真实时间恢复，与棋盘主时钟、炸弹、冻结道具的游玩tick分开。
3. 每局首次有效选中一个当前可操作的活动块，或首次成功使用现有道具时，作为该局体力开始：当前没有无限体力则扣1点，有无限体力则不扣。有效选中即足够，不等待第一次实际跨格或完成拖动。仅点击空白、冰住/锁住/不可操作块、加载或教学界面、暂停/退出、道具失败请求及只进入火箭瞄准模式不单独扣心；火箭成功选定可清除目标才属于成功使用。
4. 体力开始是一次性账户事件，与PuzzleModel.started及原有计时启动分开。不能为改体力而把即时开钟改成等待点击，也不能把开局倒计时自然归零但从未发生有效操作的局补扣1点。现有legacy开钟及成功冻结启动的特例继续适用。
5. 同一局一旦已完成体力开始，不因再次点击、拖动取消/撤销、暂停恢复、后台恢复或无限体力中途到期而重扣。余额因本局开局扣到0仍可继续本局；开始时因无限体力免扣，本局中途到期不追扣。每次重新开始/重试或换关是新局，新局资格要求体力大于0或无限体力有效。
6. 普通失败或主动退出不返心，也不额外扣心；未触发首次有效操作就退出不会仅因退出新增消耗。重试按新局处理，不在点重试与首次有效操作两个时点重复收费。
7. 通关结算当刻没有无限体力时增加1点；当刻无限体力有效则不加。这一判定不依赖该局开局是否真的扣过心：无限开局但通关前已到期，通关仍+1；普通开局但通关时无限生效，不返心。一次通关只结算一次，重新打开结算页、重试保存或恢复待结算事务不能重复返心。
8. 正常奖励和通关返心允许使余额超过5，不能被归一化、存档、显示或领取条件无声截断。超过恢复上限时自然恢复停止，之后消费至缺心才恢复计时；不为了与竞品对齐改现有旅程奖励的数量或无限体力奖励分钟数。

### B. 无限体力、补满及商业接入边界

1. 无限体力以真实截止时间判断，当前时间严格小于截止才生效，等于截止已到期。新奖励在仍有效的旧截止后叠加时长；旧截止已过则从当前时间追加。暂停、后台和离线均正常消耗此真实时长。
2. 获得无限体力只延长截止，不主动补满、不抹去或冻结普通体力恢复进度。无限期间普通缺心仍按30分钟周期恢复；无限结束不凭空补满或清空余额。体力扣返按各自发生当刻是否无限生效判断。
3. 金币补满价格为360，缺少1点与缺少5点价格相同，补至普通恢复上限5。补满前先按当前真实时间结算自然恢复；已满或超过5不扣金币、不减少余额，金币不足不补满。余额足够且确实缺心时，将金币扣除和体力补满作为一次可恢复、幂等的持久化事务；重复点击或保存结果未知不能重复收费或免费发放。补满不取消既有无限体力截止。
4. 竞品已确证高级通行证premium将上限设为8，广告/广告跳过成功回调在未满时+1。本仓库GameHost/WebHost/WechatHost目前没有激励广告、支付或premium资格接口；本版仅记录这两项竞品事实与我方未接入边界，不伪造资格、奖励回调或广告按钮，不声称整个商业系统完全一致。后续真实接入时应单独核验资格与成功回调。
5. 竞品离线/资源检查的每1800秒+1、未满保留余数有明确原生证据；在线协程存在先AddHeart再递归恢复检查、随后重置锚点的疑似重复恢复顺序，本轮未动态复现。本版采用明确的每1800秒+1及离线保余数，不把该未复现异常写成产品规则，也不宣称逐指令复刻竞品全部缺陷。

### C. 持久化、界面与验收约定

1. 以下是落实用户目标的实现约定，不声称用户逐项另行指定技术方案。每局通过activeRun.lifeStarted持久化记录是否已完成体力开始，并与准备扣心的事务关联；只有扣心/免扣标记已获得可靠保存确认才允许该首次操作生效。保存失败拒绝该次操作并可重试；结果未知先核对已落盘事务，不能既扣两次也不能凭未知状态免费开局。旧存档缺少lifeStarted时sanitize兼容为false，启动的recoverInterruptedRun仍按既有中断局退出规则清除journal，不追溯补扣旧局；之后生成的新局首次有效操作按本版扣心。lifeState既有余额、下次恢复时刻、无限截止三个字段保持，不清除合法余额或上限外奖励。

3. 十语言的空体力、开始保存失败/未知、金币补满、已满和成功反馈须匹配实际行为；需要时显示真实恢复倒计时。旧“失败才扣心”或“奖励最多5”文案不可继续误导。未接入的BP/广告不渲染可完成的假入口。

## 0. v1.14时间冻结：用户要求、实现约定与v1.14.1文字澄清

## 0.1. 承继v1.13的翻门动画事件合同

1. 用户明确授权的是翻门等待离场动画完成。每次本体移除或成功剥层，仍使全部翻转门各切换一次，包括本次所用门；移动、失败出门和仅播放无效动画均不产生翻转。门色、触发次数及触发对象范围不改。
2. 开始离场时按原规则结算本体移除/剥层、冰门/可见冰块/卷帘减数、钥匙与锁、剥壳拆弹及既有空间投放/揭层；只有翻门切换延后。钥匙仍须本体移除才释放，剥层不释放钥匙；此版本不借竞品差异改其他机制。
3. GUI中，每次有效离场登记一项待完成翻门事件；对应本体离场或外壳剥离动画结束后，由有效完成回调提交模型的实际open切换，并在此时开始门的翻转表现。普通出门以主体完整吸入完成为节点，其后装饰碎屑不延迟翻门；剥壳以该次外壳剥离动画完成为节点。等待期间门的实际通行状态保持原值，不能模型先翻、仅把视觉延后，也不能让动画绕过模型独立改规则。
4. 多次离场分别产生独立事件，每项只能完成一次；不能以“已有待翻转”合并或丢弃第二次事件，也不能因重复回调多翻一次。动画重叠时，各自在自己的有效完成时点结算；同一门最终状态由实际完成次数决定。等待翻门不全局锁住输入，其他合法操作仍按当时真实门状态判断。
5. 暂停及切后台不推进离场完成、不在后台用计时器偷偷翻门；恢复后随仍有效的动画继续并完成其事件。失败、重开、换关、离开本局、撤销或取消导致原动作被作废时，原动画的陈旧回调必须无效；快照恢复、模型替换或重复回调不能重新触发已完成/已作废事件。

## 2. 空间、颜色、开局与形状硬规则

## 4. 结算与一致性

1. 每次整块或剥层只计一次清除：开始离场按原时点使冰门/可见冰块/卷帘减数，登记一次全体翻门事件并在对应动画结束时实际切换；不因露内芯或完成回调再扣一次其他计数。钥匙只按本体移除结算。headless无动画模式即时完成该翻门事件。
2. 先按本次事件前可见性扣冰，再揭卷帘/电梯；新露冰不追扣。炸弹解除最后限制当帧不追扣以前时间，未选中也会计时。
3. 投放/揭层确定性串行，完整足迹无碰撞，必须终止。自动投放的已发生事件、拖动取消与撤销保持一致，不丢块、不复制，不回拨墙钟。
4. 电梯不只检查原成员ID是否消失；任意外来块压区也要等待。隐藏批次整体释放，不产生跨层同时占格。
5. 结束、失败、暂停后不得继续投放、重复清除/翻转或计数穿零；仍有效的末次离场及暂停后恢复按第0.1节处理，失效回调不补发。快照、克隆、撤销及独立回放的冰/门/队列/炸弹、冻结剩余与待完成事件状态一致；旧回调不得越过恢复后的事件有效性检查。
6. 视觉动画不独立扣数或改open；GUI有效离场完成回调提交模型翻门事件，视觉表现同一模型结果。旧运行兼容路径保留但不作为新数据机制；本次21–200显式使用runtimeProfile v1.4（`revised-2026-09-23-v1.4`），承继v1.13动画时序并实现时间冻结；不能只换标签而未实现对应行为。
