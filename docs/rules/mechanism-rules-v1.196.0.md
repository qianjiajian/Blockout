# 激励广告提前加载 v1.196.0

- Rule ID: blockout-rules-v1.196.0
- Runtime profile: revised-2026-09-27-v1.5
- Frozen on: 2026-10-12
- 完整承继v1.195.0及历史合同，仅调整激励广告资源准备时机与宿主生命周期管理。

用户反馈手机点击广告按钮后需等待约1秒，在获知当前每次点击才创建和加载广告、可通过提前加载减少等待后，明确要求“优化”。本轮允许在点击前准备广告资源，取代v1.184“仅用户明确点击后请求广告”对资源请求时机的限制；展示广告和开始奖励领取事务仍必须由玩家明确点击触发。

## 提前准备与展示边界

- 微信宿主在前台启动、恢复前台，以及一次已展示广告完整观看或主动关闭后，可提前创建并加载一个待用广告实例。重复预热复用同一待用实例，不重复创建或重复加载；不得预先弹出广告、创建奖励领取记录、发奖、扣次数或修改玩家存档。
- 玩家点击时，已准备好的广告直接请求展示；尚在加载时复用同一加载过程。没有待用广告时才创建并加载新实例。加载时间与平台展示时间仍可能存在，不保证所有设备或网络下立即弹出。
- 每次展示使用独立的原生多例广告实例（multiton），保持请求ID与该实例回调隔离。展示期间拒绝并发请求；完成、取消或失败后释放对应实例，旧回调和迟到的加载结果不能影响下一次广告或奖励。
- 预加载失败只清理对应实例，不循环自动请求、不影响游戏启动、不触发奖励错误结算；后续明确展示请求或恢复前台可重新尝试。未配置或不支持的环境仍不可用，不采用伪广告或模拟完成发奖。

## 后台与实现策略

- 游戏隐藏后不新开展预热或展示，尚未展示的活动请求取消；已经展示的广告保留原生关闭回调，不能因广告自身导致游戏隐藏而取消合法观看及奖励资格。恢复前台时幂等准备下一条。
- 当前实现采用待用缓存加载成功后5分钟的本地刷新策略，在再次预热或使用时检查；广告加载30秒未完成则清理并返回失败。两者是本轮实现策略，不冒称用户指定参数、微信SDK有效期或平台时限保证；不得以这些计时器判定完整观看或授予奖励。
- 清理前标记实例已结束，独立解绑并销毁；销毁触发回调、同步异常、加载超时及迟到完成均不得重复结算。宿主释放后不再预热或展示。

## 保持项与验证

- 完整观看仍由实际原生完成回调确认；提前关闭、无填充、加载或展示错误不发奖、不扣次数。完成请求仍防重放，所有广告入口继续共用既有宿主接口。
- 福利站、体力、道具和每日挑战等既有奖励额度、资格、跨日归属、保存拒绝或未知候选事务、领取音效和资源动画保持，不因预加载开始任何奖励或存档操作。
- 验证预热幂等、热缓存展示、加载中点击、并发拒绝、旧回调隔离、错误与超时、前后台交错、缓存过期及释放；隔离模拟宿主的验证不能冒称微信真机广告验收。
- v1.195全国候选合并、关卡与经济、主线/每日/联赛边界以及全部其它历史合同保持。仅实施本地代码与验证，不自动微信打包、上传或发布，不访问真实玩家存档；进度与证据另记WORKSTATE，不将规则登记当作实现完成。
