## 本版新增：优先已解锁高级机制，允许多种机制组合

用户在21–30第二轮重做中追加：“关卡优先已解锁的高级机制，22块棋盘上都没机制”，随后明确：“允许多种机制叠加”。本版登记这一设计要求，不改变任何机制的运行语义，不提前解锁后期机制。旧23份冻结正文和manifest条目保留。

1. 后续关卡设计优先采用到该关已解锁的较高级机制；当前实际改图范围仍仅21–30。就本批而言优先考虑卷帘、外壳与数字冰等棋盘内机制的决策作用，冰门及异形空间可以组合使用。不能只在标签中写高级机制，或仅靠外围冰门和普通色块搬运来回应第22关棋盘内缺少机制的反馈；第22关须补入可辨识且真正影响解法的棋盘内机制。
2. 允许多种已解锁机制在同关组合、共同形成核心解题链，不再以“每关只能一个主机制、其余不得形成并列核心负担”为拒绝组合的依据。可以保留一个清晰主要目标，也可以由机制组合承担重点；逐关说明各机制的用途与联动，保持信息可理解、错误原因可解释。不强制每关多种，不设用户未要求的机制种类/数量上限或必须使用最新一种机制的配额。
3. “叠加”是设计组合许可，既有兼容限制及生命周期不变；同一块或区域仅可采用现有模型与美术已经支持的合法组合。不是允许互相冲突的配置、额外外壳层、彩格关外壳、队列冰、假卷帘或突破8色/门宽/真实空间等硬规则。21–30仍不得加入生成器、轴向、钥锁、电梯、星门、炸弹、翻门、彩格等未到解锁关的机制。
4. 组合须落实为多格色块之间的让位、可用工作位、剥层后的持续占位、揭帘/解冰先后等真实选择，不能以机关数量、计数高低或重复单格搬运冒充难度。v1.18关于顺序/预判/空间/错误后果、公平性、完整无道具路线、自然时间输入及玩家盲测分离的评审保持；可比对照逐项放宽或明确其组合归因，不能把多个同时变化的条件归功于单一机制。
5. 继续按v1.20自主设计、验证并生成正式21–30，无需逐关再找用户确认。棋盘结构、原难度标签及普通≥10/困难≥15/超难≥20必要腾挪下界保持，其他190关、原时间/实际三星/奖励、机制逻辑/UI资源/提示/存档不改。仍须新具体数据的完整回放、硬规则、下界和最终正式入口验证；旧候选仅能作素材，改图后重新核验，未通过不冒称完成。
6. 原图/历史候选/证据保留；本版仅设计合同更新，锁定文档不代表新地图已生成或可解。时间与三星标定、真人体验和微信真机验收另列，不自动上传发布。

以下完整承继v1.20正文；与上述高级机制优先、多机制共同核心许可冲突的历史单主/少辅解释由本节取代，其他范围与硬规则保持。历史“本版”“当前”按原版本语境读取。

## 承继v1.18：机制难度与合理性评审，协作重做21–30

### 用户采纳与本轮范围

用户明确：“采纳，接下来配合我来重新制作21-30关”。本次采纳上一轮提出的机制难度与合理性评审方法，并确定协作重做第21–30关；不是只凭必挪或机关数量评分，也不是新批准一套数值门槛。旧20份冻结正文和manifest已有条目保留，棋盘runtime不变。

### 采用的设计与评审方法

1. 每关先写明“利用哪个主机制，解决什么具体问题”，承继v1.17单主机制/明确辅助原则。检查主机制是否影响核心解题决策，是否能被简单清场普遍绕开，以及玩家能否理解其作用。教学关可以重点表现因果，不要求所有机制出现时都达到高难；本条不自动改变关卡难度标签。
2. 分别记录顺序选择、提前规划、空间取舍、错误代价。难度来自有后果且可推理的选择，不以机关数量、计数高低、动画长度、总拖动数或重复搬运代替。必要腾挪保留为一个独立指标，不能据某条绕路宣称全路线最小下界，也不能因采用多维评审而取消已明确批准的下界合同。
3. 合理性检查包括信息足够、规则与反馈可理解、错误原因可解释、补救/重试能带来学习、理解解法后正常操作可执行。隐藏机制不应要求初见玩家猜未知内容才能避免无预警必败。记录是否能补救及代价，不据此擅自规定所有错误都必须可逆或要求唯一解。
4. 需要判断主机制贡献时，可在隔离分析副本中放宽相关限制作对照，比较核心思路、顺序及路线变化；不能直接删实体制造额外空间、提前揭层造成重叠，或同时改变多项条件而混淆结论。对照不是正式玩法、正式路线或难度证书；步数差也不是机制难度总分。不合适做可比对照的机制采用解题过程分析并说明限制。
5. 程序验收先检查当前硬规则、完整无道具通关路线与独立回放，再检查正式入口真实拖动、动画和自然时间下可执行；检查绕过考点的意外捷径，不强求唯一解。保留包含所有后续批次的完成目标、真实倒计时及本游戏机制，不以放宽副本代替正式模型。
6. 玩家体验与程序验证分开：由已学过前置机制但未见过本关解法的玩家试玩，并区分其熟练程度。观察理解错误、顺序卡点、失败原因（决策/误操作/时间）、重试及理解后表现。无真实玩家证据时标待试玩，不把设计者/自动回放当盲测，不把小样本当稳定通关率；首过率/耗时等阈值须结合后续实际结果另定，不能本次凭空冻结。
7. 每关保留简明评审卡：主机制、核心决策、容易选错的地方、可用线索、补救方式、可解证据、试玩卡点；同时注明辅助机制用途、数据版本及待验证项。先以代表关统一口径，再根据证据评审后续关；评审记录不等于完成证明。

### 协作重做的实施边界与待确认项

1. 本轮范围为21–30，按用户逐步协作确定设计；先明确主机制/核心决策与布局草案，再制作候选、验证和交用户体验，不在仅确认评审方法后直接批量覆盖正式地图。具体每关设计与验收按后续明确意见推进，其他190关不因本任务改变。
2. “重新制作”的几何与数据范围仍待用户确认：是否可改棋盘尺寸/轮廓、出口、机关种类数量及初值，还是保留部分结构仅改色块。Lv21此前“只改色块、必挪至少15”的限制是否继续适用亦单列询问；答复前不能默认为撤销。Lv26等原有明确约束同样不因泛称重做无声消失；确需变更时把新决定与旧合同差异明确记录。
3. 已解锁机制范围、8色出口唯一/宽度、满铺、相邻异色、异形比例、真实卷帘及其他硬规则保持；不提前引入后期机制，不通过改运行规则来让候选过关。当前接受的是评审方法，不是固定六阶段教学周期、辅助数量上限、全季必挪验收恢复或首教关统一降难。
4. 原正式时间、实际三星目标、奖励、解锁提示、UI资源和用户存档保持，冲突另行报告并在明确决定后处理。旧原图/证据保留，候选变更后重新验证，不复用旧布局证书；不自动上传发布。
5. 上述逐步协作与待确认处理是落实本次任务的执行口径，不声称用户已经逐项批准未回答的方案。规则冻结、布局制作、无道具可解、真实时间输入、必要下界、玩家试玩、用户确认及正式接入分别记录。

以下完整承继v1.17及其承继正文。历史“当前”“本版”和当时任务范围保留原语境；本版新增的21–30协作任务及评审方法优先，待确认事项不能从旧概述或新任务泛称中推断成已批准。

## 承继v1.17：每关突出一个主机制，辅助机制少而明确

### 用户明确采纳的原则

> 除基础移动和出口外，每关突出一个主机制，辅助机制少而明确。

本版仅将这一条纳入后续关卡设计和评审要求；不把同轮其余建议一并视为用户批准。该条是设计组织原则，不是棋盘机制行为变更，因此runtime及200关profile保持不变。旧19份冻结正文和manifest已有条目保留。

### 实施口径与授权边界

以下是执行这一原则的审核口径，不声称用户逐项另外批准了数值或技术方案。

1. 主机制按本关主要教学目标或核心解题决策确定，明确一个重点；不是按机关实例最多、某种颜色最多或出现次数最多自动判定。一个主机制可以有多个实例；仅贴上“主机制”标签，不能代替对实际解题过程的检查。
2. 辅助机制应数量克制、作用明确，服务或衬托主机制，避免多个机制同时成为并列的主要学习负担。“少”暂不设固定种类数、实例数、占比或操作次数上限，也不要求每关为了凑辅助而添加机关。设计或评审时列明主机制、核心决策及各辅助机制的用途；尚未逐关核查的正式关卡不能直接标为通过。

1. 用户明确授权的是翻门等待离场动画完成。每次本体移除或成功剥层，仍使全部翻转门各切换一次，包括本次所用门；移动、失败出门和仅播放无效动画均不产生翻转。门色、触发次数及触发对象范围不改。
2. 开始离场时按原规则结算本体移除/剥层、冰门/可见冰块/卷帘减数、钥匙与锁、剥壳拆弹及既有空间投放/揭层；只有翻门切换延后。钥匙仍须本体移除才释放，剥层不释放钥匙；此版本不借竞品差异改其他机制。
3. GUI中，每次有效离场登记一项待完成翻门事件；对应本体离场或外壳剥离动画结束后，由有效完成回调提交模型的实际open切换，并在此时开始门的翻转表现。普通出门以主体完整吸入完成为节点，其后装饰碎屑不延迟翻门；剥壳以该次外壳剥离动画完成为节点。等待期间门的实际通行状态保持原值，不能模型先翻、仅把视觉延后，也不能让动画绕过模型独立改规则。
4. 多次离场分别产生独立事件，每项只能完成一次；不能以“已有待翻转”合并或丢弃第二次事件，也不能因重复回调多翻一次。动画重叠时，各自在自己的有效完成时点结算；同一门最终状态由实际完成次数决定。等待翻门不全局锁住输入，其他合法操作仍按当时真实门状态判断。
5. 暂停及切后台不推进离场完成、不在后台用计时器偷偷翻门；恢复后随仍有效的动画继续并完成其事件。失败、重开、换关、离开本局、撤销或取消导致原动作被作废时，原动画的陈旧回调必须无效；快照恢复、模型替换或重复回调不能重新触发已完成/已作废事件。
6. 最后一件有效离场也保留恰好一次翻门结算，不能因提前标记棋盘已清空漏掉其有效完成事件；真正终止本局或该事件被作废后不得补发。失败与本局撤销的既有状态恢复规则保留，不以此授权修复或重新定义其他撤销行为。
7. 玩家火箭沿用现有一次整块清除事件及其他效果；它触发的一次全门翻转等该次主体收缩/消失动画结束再生效。不改为竞品的单格火箭，不新增道具或改变库存/价格。
8. 无动画的headless模型把离场视为立即完成，保留动作后稳定态求解与独立回放语义；GUI必须显式启用等待动画完成的模式。headless即时完成只是明确的执行模式，不是允许GUI跳过动画事件；只测headless不能证明新动画时序正确。
9. v1.13已对21–200引入离场完成翻门；本版本继续承继并按第0节迁移到runtimeProfile `revised-2026-09-23-v1.4`。1–20仍保留legacy，现有前20关无翻门。关卡几何、块/门/队列/区域配置、奖励、总时限、实际三星目标及用户存档保持；仅时间道具按第0节统一替换，不能将旧空间/翻门profile悄悄解释为新延迟行为。
10. 新模式须分别验证开始离场前后、动画未完成、有效完成、重复完成、并发离场、末次离场、暂停/后台及失败/重开/撤销后的陈旧回调。旧稳定态路线与历史证据保留，但不得冒称已通过v1.13自然时间、Pointer输入或动画验收；变更后的实际文件和运行态须重新绑定证据。

## 2. 空间、颜色、开局与形状硬规则

- 使用现有8色。每色最多一个非星实体出口；有对应星块时允许再有一个同色星门，同类同色不得重复。冰冻、翻转属性不增加颜色名额；多个实体口分别计数，不以同ID、多portal拆门绕过。
- 出口通常至多3格。仅同色可通行块在该方向的完整横截面超过3格时，扩大到实际所需宽度；2×2面积4不是4格门理由。宽块不以细柄钻窄门，不拼接门口，不只缩画面而保持大碰撞。
- 所有块的实际足迹必须可玩且同一活动层不重叠。棋盘、出口、机口、卷帘使用同一实际几何；棋盘缺口和分隔不可穿越。不用装饰、假墙、假隐藏掩盖问题。
- 生成器位于真实棋盘边缘，机体不与出口及其他机体重叠。队列固定顺序与固定落点；每件完整足迹合法且包含机口中心相邻格，不远端寻空位、不仅触碰侧口。所有队列块禁冰。
- 卷帘必须有实际矩形覆盖区和真实隐藏块，每个隐藏块完整足迹位于其卷帘中；不同卷帘不重叠，不覆盖无关开局块；隐藏区域无需自身填满。电梯按实际区域占位判定。
- 开局按初始化自动投放/揭层及动画结束后的首个可操作稳定画面计数。该画面每个可玩格由可见块实际足迹或尚未揭开的真实卷帘覆盖；隐藏/队列本体、门、装饰、空地格不能充覆盖。
- 开局不同可见块正交相邻必须异色；不约束玩家移动后。外壳按当前外色计，内外层算同一独立块。
- 异形块按非完整矩形足迹识别，开局与全关分别不超过独立块数的30%，不按面积，不用新增块稀释已有锁定数量；本批原创块数在设计规格中明确。
- 色块整体平移，不旋转、不拆分。使用当前已有完整切图支持的形状及外壳组合，不引入不可见大块或缺图块。原图资源和UI不因本次地图重做改写。
- 不使用非空间staging、旧时间/按动作次数生成器或旧装饰机制凑数量。

## 4. 结算与一致性

1. 每次整块或剥层只计一次清除：开始离场按原时点使冰门/可见冰块/卷帘减数，登记一次全体翻门事件并在对应动画结束时实际切换；不因露内芯或完成回调再扣一次其他计数。钥匙只按本体移除结算。headless无动画模式即时完成该翻门事件。
2. 先按本次事件前可见性扣冰，再揭卷帘/电梯；新露冰不追扣。炸弹解除最后限制当帧不追扣以前时间，未选中也会计时。
3. 投放/揭层确定性串行，完整足迹无碰撞，必须终止。自动投放的已发生事件、拖动取消与撤销保持一致，不丢块、不复制，不回拨墙钟。
4. 电梯不只检查原成员ID是否消失；任意外来块压区也要等待。隐藏批次整体释放，不产生跨层同时占格。
5. 结束、失败、暂停后不得继续投放、重复清除/翻转或计数穿零；仍有效的末次离场及暂停后恢复按第0.1节处理，失效回调不补发。快照、克隆、撤销及独立回放的冰/门/队列/炸弹、冻结剩余与待完成事件状态一致；旧回调不得越过恢复后的事件有效性检查。
6. 视觉动画不独立扣数或改open；GUI有效离场完成回调提交模型翻门事件，视觉表现同一模型结果。旧运行兼容路径保留但不作为新数据机制；本次21–200显式使用runtimeProfile v1.4（`revised-2026-09-23-v1.4`），承继v1.13动画时序并实现时间冻结；不能只换标签而未实现对应行为。
